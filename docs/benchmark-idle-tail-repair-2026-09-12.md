# 空闲 CPU 与等待预算修补（2026-09-12）

状态：实施及计划内验证已完成，**未通过验收**。不得提交、发布或更新装配指针。自适应等待不采用，工作区保留固定等待实现供继续修复与审阅。

历史基线固定为 `1990c84`，其空闲超限如实保留；历史比较仅候选承担一个核 1% 的绝对空闲预算，但两侧测量均须有效。同库控制两组都承担预算。性能、CPU/request 增加不得超过 5%，两侧绝对重复性均须在 ±5% 内；不筛选轮次、不拼接旧成绩。

## 实现

- Switch 仅在实际转发后开启 200µs 窗口。维护超时、空通知均不重新开启窗口，保留 1ms 维护、活跃阶段让出 CPU 与通知序号先读顺序。
- C wait 每个有限自旋段只固定一次注册引用，逐次在 RX mutex 下检查 ACTIVE/CLOSED 后探测；返回及休眠前释放引用。固定方案每次调用累计最多 50µs，并受调用截止时间限制；唤醒与维护不补充预算。实际接收校验、心跳和 Switch 身份检查保留。
- 独立诊断构建记录实际 FUTEX_WAIT/FUTEX_WAKE、返回值、errno、通知序号、单调/线程 CPU 时间和 PID/TID。结合进程 maps、共享内存 inode 和编译生成的偏移表解析信号及 RX 槽位；另记录 Switch 窗口开启/维护事件。旧等待计数改称 `wait_helper_calls`，不能据此断言内核阻塞。
- Go runtime trace 只注入诊断端点，在 pingpong 预热后启动，保存正式采样起点的单调时间标记。
- 独立自适应变体使用每句柄进程内原子 EWMA：初值 25µs、权重 1/8、预算两倍并夹在 5–200µs；累计预算不重置。锁忙样本排除，超时、成功等待超过 1ms、调用间空闲超过 1ms 复位。
- 历史比较、冻结复测与 PHP full 同库控制同步空闲预算语义。JSON 保留原字段，增加预算作用对象、测量有效性、诊断能力和执行器指纹；每轮重新记录环境。

公共 C ABI、共享内存布局、Go/PHP 签名不变；C 仍为唯一校验规则来源，保留已有 PHP 容量记忆和直接解包优化。产物不提交。

C 单因素 10 秒空闲中，端点 CPU 从 21.577ms 降至 12.054ms，但 Switch CPU 为 100/110ms，总量仍超预算。Switch `/proc/PID/stat` 量化单位为 10ms，不能把单个 tick 的差异称为显著改善。自适应端点 CPU 为 11.138/11.378ms，总量差异同样主要来自一个 Switch tick；延迟、CPU 与重复性均不足以支持采用自适应。

## 实际 futex 与 Go 诊断

第一次 `diagnostic` 保留 68 次尝试，其中 64 次因缺少端点实际 futex 日志失败，不能当作完整证据。原因是部分语言退出时不运行 C 析构。独立诊断增加句柄关闭时显式刷新及刷新互斥；关闭插桩后 safe/unsafe 两种预处理产物与冻结 fixed 完全一致，证据为 `diagnostic-flush-production-equivalence.json`。

新目录 `diagnostic-2` 的 68/68 组采集通过：204 份实际信号日志，无截断，665 个信号地址关联全部解析；12 份正式采样 Go runtime trace，保留 phase 标记。原始证据及汇总在 `diagnostic-2/evidence-summary.json`，Go trace 解析结果在 `runtime-validation.json`。

| 事件 | 次数 |
|---|---:|
| FUTEX_WAIT 调用 | 117507 |
| 其中返回 0（唤醒） | 15836 |
| 其中 EAGAIN / ETIMEDOUT / EINTR | 2318 / 99289 / 64 |

这些记录证实进入了系统调用，并区分不同返回路径；EAGAIN 不等于阻塞。墙钟与线程 CPU 差值不能进一步拆成确切的 futex 阻塞和可运行调度时间，未定部分不强行归因于 WSL 宿主。

32 组具有完整端点时间关联，26 组保留有序 ACK 样本和库等待记录，10 组缺少其他语言端点时间戳，不能做完整 RTT 分段归因。诊断主矩阵走 DIRECT，没有实际转发，因此窗口开启事件为 0；维护事件不能据此解释 routed 首帧延迟。实际 Switch 转发另由下述路由补测覆盖。诊断采集通过不等于性能验收通过。
