# 固定等待与维护调度续修（2026-09-12）

状态：本轮局部实现与验证结束，**整体计划尚未完成，性能未达标**；禁止提交、发布和更新装配指针。历史基线继续固定为 `1990c84`，不改变阈值、样本数、10000 帧预热、WSL2 及既定绑核。新增结果独立保存在 [idle-tail-continuation-20260912](../../datarouter-benchmark/results/idle-tail-continuation-20260912)。

## 实现与冻结

- Switch 增加专用 10ms 空闲等待上限，注册等待仍为原 1ms。TTL、死亡进程检查、日志和控制恢复使用独立截止时间；空通知不会延后维护截止时间。毫秒信号 API 向上取整不足一毫秒的等待，到期工作不进入信号等待。
- 无遗留请求/释放状态时每 10ms 扫描；发现遗留请求、DRAINING 或 RELEASING 后按 1ms 扫描。控制请求、损坏通知到达时立即清理并处理，保留异常写入者恢复。仅使用既有原子就绪位跳过空队列；只有真实转发开启 200µs 窗口。
- 等待唤醒后共用一次注册引用，复用心跳和非权威探测；超时唤醒仍强制核查 Switch 身份，截止时先观察可能到达的帧。休眠前释放引用，权威接收规则仍在 C。
- 原始 `current`、首版 `switch/wait50/wait100/wait200` 和修正版 `*-v2` 源码分别冻结。首版安全测试发现注销后立即重注册可能 BUSY：控制请求到达时须先完成释放清理；修正版恢复该顺序，不覆盖首版证据。
- 50µs 保留为工作区默认；100/200µs 只存在于实验目录。公共 C ABI、共享内存布局与 Go/PHP 签名不变。

## 独立诊断

C 端新增独立收发边界日志（routed-send/direct-send/authoritative-recv），包含单调时钟、线程 CPU、PID/TID、RX 槽位及通知序号；覆盖所有语言绑定，在关闭句柄时显式刷新。关闭插桩后 safe/unsafe 预处理代码与冻结 50µs 修正版完全一致，证据为 `diagnostic-production-equivalence.json`。

Go runtime trace 增加单向 ACK 预热后的正式阶段入口。诊断结果只证明采集与关联情况，不参与未插桩产物的性能门禁。墙钟减线程 CPU 的残差不能精确区分阻塞与可运行调度；锁忙计数不能独立证明它造成 RTT 尾部。

## 诊断完整性与归因边界

断电前跨语言独立诊断完成 48/54 组，6 组缺少 Go 单向 ACK trace。原因是执行器只为 pingpong 设置 trace 路径；修正后以新目录 `diagnostic-ack`、经指纹验证的原诊断产物补测，6/6 组通过。原失败记录保留，两组不是性能成绩。C 边界补齐其他语言进入/退出传输层的时间戳；语言运行时在 C 之外的工作仍不属于这些记录。

断电后的 `routed-diagnostic` 使用两份重新构建的独立插桩源码，关闭插桩后的 C 预处理结果与原冻结产物一致（`routed-diagnostic-equivalence.json`）。增加逐帧正式起点与共享内存 maps，8/8 组采集通过，40 份 futex/C 边界 trace 完整；该入口明确标记 `instrumented=true`、`gate_eligible=false`，不运行或宣称通过性能门禁。生产探针的默认路径保持原样。

`routed-diagnostic/routed-analysis.json` 将首帧与实际 futex、PID/TID、通知序号及 RX 槽位对齐，所有信号地址均解析。10ms 首帧每组最慢 100 帧中，发送端 96–99 帧进入耗尽自旋后的信号等待，接收锁忙观测为 0；发送端等待区间占 RTT 的中位数约 59.5%–62.8%，两侧完全落在帧区间内的接收 CPU 合计中位数约 12.1–12.4µs。

这些证据将后续关注点收窄到等待/唤醒路径，但不能把 futex 墙钟时间全部当作阻塞，也不能把墙钟减线程 CPU 残差全部当作可运行调度。没有逐个尾样本的精确阻塞/调度分解；接收 CPU 数值包含插桩影响，不能作为生产耗时。未定位的部分保持未定，不据此进行下一处推测性修改。
