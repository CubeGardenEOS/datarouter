# KEEP 当前契约（layout 17 / KEEP layout 3）

旧版 layout 13 的 seqlock 方案已被本轮安全修复替代；复制后复检代次不能消除
并发覆盖引起的数据竞争。历史设计不再作为实现依据。

- C 为校验与数据操作的唯一事实来源，Rust 仅委托 FFI。
- 区域 ≤8 MiB；条目按 8 字节对齐，空键不是尾部填充标记。
- 复制读取持有独占引用直到复制完成；旧 tuple 零拷贝读取用 `verify_ref` 释放对应引用；
  Rust guard 自动持有映射并释放引用，释放后不能再访问指针。
- 当前读引用也是独占的，其他 KEEP 操作返回可重试 `AGAIN`。
- PID 与所有权一起原子发布，不能抢占仍存活的暂停进程；确认死亡后在独占状态
  下整体清空缓存。PID 复用保守延迟恢复，不用缺失身份字段推断进程已死亡。
- 槽位、条目与映射范围先验证；短缓冲返回所需长度；TTL 溢出拒绝。
- 前缀失效完成整个有限区域的扫描。

本候选尚未完成全部安全与性能门禁。具体证据、接口限制和剩余项见
[2026-09 安全审查](security-audit-2026-09.md)。升级须停止旧 switch 与所有消费者、
仅清理该实例共享内存并统一重编译；不允许新旧布局混跑。


Rust `Frontend::keep_reference` 返回 RAII guard，自动持有映射与 C 读引用，可跨线程并在
frontend 销毁后继续使用；guard 销毁时释放引用。原有 get_ref/verify_ref 的 tuple 接口保留，
Rust 返回的 seq 是不透明引用 token；适配层在 verify_ref 结束时释放原映射，即使 frontend
已重连到新 switch。忘记验证会泄漏引用，应优先使用 guard。

注册 I/O 引用在一个 64 位原子中绑定 route_id、关闭位和引用数，防止迟到的引用增量跨代次
进入复用槽位。路由代次耗尽后该槽位不再复用，需新 switch 映射；不再回绕到旧 route_id。
