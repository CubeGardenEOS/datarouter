# 小包自旋路径缓存扫描

本轮为源码、结构偏移和实际远端测试产物的反汇编检查，未修改运行时代码，
未启动服务或重新停服。不能据此给出各项成本的百分比或声称性能已经恢复。
候选源码与上一轮 manifest 的 src/include 指纹核对结果及反汇编存于
`../../datarouter-benchmark/results/remote-stable-20260913/cache-scan/`。
稳定版是取回的实际业务产物，不能用本地历史源码差异代替它的精确源码身份。

## 目标

使轮询的指令与控制状态保持紧凑，减少跨核写入和 payload 之外的访存。
自旋和绑核减少睡眠唤醒、迁移带来的损失；缓存驻留由硬件缓存替换和一致性
机制等共同决定，操作系统调度也会影响它，绑核不是 L1 驻留保证。
不同核心的生产者和消费者仍需交换缓存行。

512KiB 环持续推进，即使帧只有 64B/1KiB，也不是一直复用同一小块 payload。
因此首先优化稳定驻留的控制工作集和当前帧的交接，不把整个环常驻 L1 作为目标。
不能简单把环缩小：这会改变突发容量和背压行为。

## 确认的问题与优先级

1. **RX 空扫做了完整 channel 构造和双游标校验。**
   `src/port.c:select_rx` 遍历全部配置槽位；每个空队列也调用 rx_channel、
   ring_used/validate，读取相隔 64B 的 head/tail。远端候选反汇编保留了循环内
   `div` 与 PLT 调用。默认 N=4 时一次完整空扫涉及 8 条队列游标缓存行；
   N=64 时为 128 条（8KiB 的游标行，不含其他状态），而非只检查活跃来源。
   优先实验：条件回绕替代循环取模；精简空扫所需的本地视图，避免为每个空队列
   计算 payload 地址。保留队列公平性、损坏检测、缓冲不足重试和代次规则。
   缓存映射地址必须以验证后的映射及生命周期为依据，不能盲信可变共享元数据。

2. **按值传递 24B channel 的成本已经进入机器码。**
   channel 是三个指针；实际 ring_validate 从栈中读取参数。跨编译单元的
   小函数未全部内联，空扫与帧头检查叠加结构传参和调用成本。
   优先实验：内部热路径只传必要的 header 指针，或提供共享的 C 内联实现，
   保持校验规则的唯一事实来源。不要以关闭校验替代优化。

3. **租约快速路径仍调用 pthread_once、pthread_getspecific、getpid。**
   已在远端候选反汇编确认。send/recv/wait 都会进入 attach，探针先 recv，
   空时 wait，再 recv，会重复付费。可实验 TLS 快速状态，但必须同时保留
   fork 子进程失效、detach、析构和失败重试语义，不能直接删除 PID 检查。

4. **心跳缓存行仍有多个写入者。**
   port 的 send/recv/wait 与 router 的 route_locked 都调用 touch_entry，
   后者写的是来源心跳。独立的 heartbeat 行避免了与身份字段的伪共享，
   却没有消除端点与 Switch 对该行的真实共享。
   可实验合并/限频更新或区分端点心跳与转发活动，但要先明确 TTL 和 drain
   语义；不能仅删除 Switch 的更新。这种竞争旧版也可能存在，不等于本次
   退化的独立原因。

5. **全局调度热点仍共用缓存行。**
   本地布局检查：request_ready_mask=72、tx_ready_mask=80、
   tx_blocked_mask=88、corrupt_slot_mask=96，均在偏移 64–127 的同一行。
   发送端、Switch 和接收端对这些位图的原子写入相互影响。
   wake_blocked 即使没有阻塞者仍执行 exchange，clear_tx_blocked 也会写入。
   优先实验读后再决定 RMW，但必须重新验证 full→登记阻塞→复查空间的竞态。
   拆开缓存行涉及共享布局兼容，不与无布局改动的实验混在一起。

6. **纯自旋仍支付 ownership 与通知屏障。**
   router 每帧获取/释放 writer_owner；post_if_waiting 在零睡眠者时仍执行
   全屏障，实际指令是 `lock orq $0,(%rsp)`。这是栈上的屏障，不应误报成
   对共享通知行的写入。通知优化相对旧版也省去了 sequence RMW，净收益待测。
   ownership 保护混写和恢复；不能凭“只有一个发送者”跳过，也不能仅凭当前
   线程 spin 就断言另一端没有 hybrid 等待者。内存序改变需要独立证明和竞态测试。

## 验证顺序

先保持布局与并发协议不变，单独比较 RX 扫描/传参与租约快速路径；随后才处理
心跳和调度原子写入。每项冻结源码、产物、CPU 分配，使用 cgeos-cli 做串行
A/B/B/A，同机两轮至少覆盖 64B/1KiB routed 与 direct，并保留大帧、空闲首帧
及多来源公平性验证。基线同时保留上一轮候选与实际业务稳定产物，避免把
优化收益和原有差异混为一谈。沿用用户更新后的相对稳定版性能评估标准。

如平台提供硬件计数器，记录 cycles/instructions、L1 数据未命中与缓存行争用；
虚拟机未暴露计数器时明确缺项，不能用 CPU 利用率或页面驻留代替 L1 命中率。
本扫描未收集这些计数器，也未证明上述因素分别解释了多少吞吐或 p99 变化。
