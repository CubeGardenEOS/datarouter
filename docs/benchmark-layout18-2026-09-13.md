# layout 18 与专用核候选：WSL2 验收记录

本候选尚未通过性能与测量有效性门禁，禁止提交、发布、更新装配指针或执行生产迁移。
实现保留在开发工作区；本报告不把局部功能通过解释为完整验收通过。

## 实现与边界

- layout 18 使用 N 个 TX 与 N² 个来源→目标 RX，每队列 512KiB；游标、写入
  ownership、身份/引用/心跳/通知按写入方隔离，payload 页对齐且初始化不清零。
  默认四端口队列数据 10MiB；64 端口约 2.03GiB，另加控制结构与 KEEP。
- C 统一负责轮询选择、短缓冲重试、FIFO、代次、注销回收、死亡写者恢复和
  SIGSTOP 活写者保护；删除逐帧 inflight 矩阵，以队列与引用状态控制槽位复用。
- auto/spin/hybrid 与 CPU 池、不同物理核租约、cgroup v2 配额、fork/退出回收、
  显式 detach 恢复亲和性；获得专用核后持续 pause 轮询。Go 每次 cgo 调用锁定
  OS 线程，解绑后才归还运行时。没有新增后台转发队列。
- 进程内 TTAS 短锁；drain 私有缓冲且回调在锁外，消费后先唤醒受阻写者再回调。
  混合等待使用登记→SC 屏障→复查，发布使用发布→SC 屏障→检查睡眠者。
- Linux 核租约作用域是同一网络命名空间。Windows 保留 hybrid；不把 Linux
  专用核验证视作 Windows 运行验收。无法识别的配额配置保守回退或拒绝 spin。
  显式 spin CPU 池由执行器在池外预留两个物理核，有限配额仍预留两个 CPU 当量。

## 冻结与门禁

证据根目录：`../datarouter-benchmark/results/layout18-20260913/`。
历史源码固定 `1990c840001a5f5effbc196ceb9f0d998a554135`；开发基于
`4b79a1601b94de24100b01cb19f63a65756fc0f7` 的未提交工作树，不能只用 HEAD
代表候选。每组结果保存源码/产物/执行器 SHA256、实际角色 CPU 和运行信息。

`stages/layout17,spin,queues,locks-v2,final-v2` 依次冻结原有 layout17/100µs、
持续轮询、分队列、短锁、按睡眠者通知。`stages/history` 是历史源码。
`stages/php-path-fix` 与 final-v2 的生产 C 代码相同，仅修正 PHP 验证器显式
benchmark 路径。最后阶段还包含通知结构的缓存行隔离，因此不能将其差值
完全归因于通知系统调用数量。

所有实验通过重建后的 `cgeos-cli`（源码 `079684e4cc51b3c121827998bd5397109899dcc5`）
执行。构建完成才计时，每个场景串行 A/B/B/A，自动选择后冻结角色分配。
本轮取消空闲 CPU、CPU/request 的性能阻断，但保留原始数据与有效性校验。
Go/PHP 性能豁免不豁免功能；其他语言退化 ≤5%，两侧重复性 ±5%。

## 安全与测量测试

`layout18-security-final/results.json`：42/42 通过，包含原有 40 项检查，
以及线程租约和完整 Switch 场景；适用的 C/Rust、静态分析、sanitizer、包构建、
Windows 编译检查均按结果中的各项记录执行。
新增场景包括索引/映射/布局拒绝、最大帧与环绕、公平性、短缓冲重试、并发接收、
混合写者、槽位复用、SIGSTOP/SIGKILL 写者、无限等待退出、回调重入、
跨进程租约争用、死亡回收、亲和性恢复，以及 20000 次 C11 发布/登记竞态。
这是执行测试，不是对所有硬件内存模型的形式化证明。

benchmark 比较、失败并集、序列与 CPU 豁免的 21 项单元测试通过。
初次从仓库根运行未设置 PYTHONPATH 导致导入失败；使用 `PYTHONPATH=tools`
后全部通过，未修改测试标准。

## C 汇聚阶段对照

`fanin-v2/results.json`：54 条有效记录，6 条历史记录因回复校验失败无效；
180 项对照中 75 项失败（包括无效历史基线、性能与重复性失败）。
候选各 2/4/8 来源场景完成且帧校验通过。每来源预热 10000、正式 20000 帧，
1KiB payload，逐帧 ACK；附加测试不计入八语言矩阵。

| 阶段 / 8 来源 | A 第一轮 fps / p99 µs | B 第一轮 fps / p99 µs | B 第二轮 fps / p99 µs | A 第二轮 fps / p99 µs |
|---|---:|---:|---:|---:|
| 持续轮询 → 分队列 | 275875 / 43.980 | 299583 / 37.410 | 291384 / 37.990 | 271312 / 39.680 |
| 短锁 → 最终通知阶段 | 300371 / 37.071 | 221877 / 50.081 | 214999 / 49.628 | 279488 / 38.638 |

分队列在该 8 来源场景有收益，但最终阶段吞吐回退且部分阶段重复性超限，
不满足合入条件。禁止挑选有利轮次覆盖失败。
该场景分队列映射从约 17.0MiB 增至约 53.0MiB；驻留从 4363 页降至
约 2573 页（4KiB 页）。这是按需触页的结果，不能把低 RSS 解释为低地址空间需求。

历史 `1990c84` 在六次汇聚中均出现回复内容校验失败；旧源码的直接写者计数
并不提供多来源互斥，与该故障一致，但没有改写历史源码来制造可比较的性能。
原始日志保存期望/实际来源、序号和时间戳。首次实验 `fanin/` 也完整保留。

## 执行器修复与补充验收

初次 `php-full/` 完成原生对照后因验证器硬编码兄弟 benchmark 路径中断。
已改为使用 CLI 显式传入的 benchmark 路径；新目录重跑，不覆盖失败证据。
`targeted-v2/` 发现 benchmark 的独立 Go cgo 调用未解绑而出现错误/超时，
因此主动结束该轮并保存 `comparison.json`（signal 15、cleanup remaining=0）。
`executors-v3` 对 Go 调用加入 OS 线程锁定与可选 detach；两侧使用同一执行器，
历史库不存在新符号时跳过 detach。Go SDK 本身已在安全/功能流程中采用该规则。

最终补充结果在完成后列于下节。所有失败期间均未提交、发布或更新装配指针。
统一停机、清理旧布局和重建端点的迁移仅可在完整验收通过后安排。
